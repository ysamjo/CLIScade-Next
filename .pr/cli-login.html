Neue API im Integrationsdienst

Additiv unter /cliscade/v1; die Agent-Server-API wird nicht ersetzt.

GET    /agents/{agent}/login           Status und aktive Challenge
POST   /agents/{agent}/login           Fester nativer Login-Befehl
POST   /agents/{agent}/login/code      {id, code} für Claude
DELETE /agents/{agent}/login/{id}      Nur diesen Login abbrechen

Authentifizierung über den bestehenden internen Session-Key. Keine vom Browser wählbaren Shell-Befehle, keine PTYs, keine Agentenprompts. Roh-Ausgaben und Tokens verlassen den Dienst nicht. Der API-Client erhält nur erlaubte Anbieter-URLs, Gerätecodes und Zustände.

Persistenz und Lebenszyklus

Beide Dienste verwenden dasselbe sessions/home. Native CLIs verwalten ihre eigenen Konto-Dateien. Codex wird nach erfolgreichem Login über die vorhandene OpenHands-Secrets-API gespeichert, damit deren versionierte Credential-Bindung Refresh übernimmt. Der separate SDK-LLM-Subscription-Store wird nicht als ACP-Anmeldung ausgegeben.

Ein Login pro Anbieter; ein doppelter Start liefert den vorhandenen Vorgang. Ohne Challenge scheitert ein Start nach 60 Sekunden, der gesamte Login läuft spätestens nach 15 Minuten ab. Browser-Schließen beendet den Login nicht. Dienst-Shutdown beendet nur seine Login-Prozessgruppen. Bei Neustart werden offene Logins neu begonnen; gespeicherte Konto-Dateien bleiben erhalten.
